# 电商交易数据用户与商品精细化分析（MySQL + Tableau）

**工具栈**：MySQL 8.0、Navicat、Tableau、SQL 聚合 / 窗口函数

## 数据说明与预处理

基于电商交易数据集（**99,457 条订单交易记录**，覆盖 2021-01 ~ 2023-03，含性别、年龄、8 大商品类目、数量、单价、支付方式、交易日期等字段），使用 MySQL 完成数据清洗与预处理，包括空值检测（关键字段缺失为 0）、重复值去重（全量核验无重复记录）、时间字段拆分（`STR_TO_DATE` 将非标准日期字符串转为 DATE，支持按年/月/星期聚合）及异常值过滤（数量 ≤ 0、单价 ≤ 0、负金额全部剔除），为后续分析提供高质量数据基础。

> **数据边界说明**：本数据集为"订单级交易快照"（每个用户恰好一条交易记录、无 pv/fav/cart/buy 行为类型字段），与天池 UserBehavior 行为序列日志不同。因此**行为序列类分析**（PV/UV、留存率、转化漏斗、RFM 的 R/F 维度）在当前数据上不可行，方案中以**交易维度分析**（单笔消费价值分层、类目×人群偏好、价格带、支付偏好、月度趋势）替代，并在末尾给出换用行为序列数据后可直接补充的模块。

## 用户维度分析

- 构建**用户结构画像**：性别（Female 57,832 / Male 41,625）与年龄段（18-25 / 26-35 / 36-50 / 50+）分布，各年龄段消费均值与偏好类目 TOP3（窗口函数 `ROW_NUMBER` 分区排名）。
- 构建**单笔消费价值分层模型**（RFM 因单次交易退化为金额 M 维度）：基于 `PERCENT_RANK` 分位将 9.9 万用户划分为**高价值（前 20%）/ 中价值 / 低价值**三层，验证**二八法则**（头部用户对销售额的贡献占比），并输出高价值客群的性别、年龄、类目、支付画像。
- 构建**用户画像聚类**：生成"人口属性 + 类目偏好 + 消费金额"特征宽表，导出后以 KMeans（标准化 + 手肘法定 K）将用户分为 4 个画像簇，输出每簇年龄 / 消费 / 主导类目画像。
- 基于分层结果制定**分层运营策略**：沿"提客单 / 提频 / 扩品类"三条价值提升路径，为高、中、低价值用户分别配置差异化运营抓手（VIP 权益、交叉销售、首购提额等）。
- *待补充（需换用行为序列数据）*：PV/UV 流量指标、次日 / 三日留存率、用户行为时间分布、浏览→收藏加购→购买转化漏斗，以及完整的 RFM 8 类用户分层。

## 商品维度分析

- 分析 **TOP 类目经营结构**：8 大类目销售额 / 销量 / 占比排名（销售额占比经窗口函数计算），识别营收主力类目（Clothing 30,771 单、Food & Beverage 15,865 单、Cosmetics 15,097 单等）与高客单类目。
- 构建**类目价格结构矩阵**：以平均单价 × 平均订单额 × 平均件数区分**高价低频 / 低价高频**类目；结合**价格带分析**（订单金额 0-100 / 100-300 / 300-600 / 600-1000 / 1000+ 分档）识别销售集中带与价格断层，为满减门槛设定提供依据。
- 构建**类目 × 人群偏好矩阵**（性别 × 年龄段）：识别各人群的主导类目，指导精准选品与推荐。
- **PV-BUY 四象限的适配替代**：本数据无 PV 指标，改以 **"销量 × 客单价"矩阵**定位类目：高销量高客单（支柱品）、高销量低客单（刚需品，如 Food & Beverage）、低销量高客单（价值品）、低销量低客单（长尾品），用于判断类目运营定位。

## Tableau 可视化与运营建议

使用 Tableau 搭建多维度可视化仪表盘，整合 **7 个分析模块**：① 全局经营 KPI 概览（订单量、销售额、客单价）；② 类目销售结构（占比 + 环形图）；③ 用户画像（性别 / 年龄结构）；④ 价格带分布（直方图）；⑤ 支付方式偏好（占比 + 平均订单额）；⑥ 月度销售趋势与环比增长（折线图）；⑦ 客户价值分层与高价值客群画像（Pareto 图 + 雷达图）。

基于分析结果输出精细化运营建议：
1. **高峰时段营销**：依据月度 / 星期销售趋势定位消费高峰，实施限时优惠与促销排期；
2. **精准人群运营**：依据"人群 × 类目"偏好矩阵做差异化选品与推荐；
3. **分层运营策略**：高价值客群定向权益、中价值客群交叉销售、低价值客群首购提额；
4. **支付渠道运营**：结合支付方式 × 客单价分布设计渠道满减策略；
5. *待回流数据*：上线后以客单价、复购率、高价值占比、类目渗透率四指标做 A/B 测试与效果验证。

## 后续扩展

若目标产出为行为序列级成果（转化漏斗、留存、完整 RFM），建议换用天池 UserBehavior 数据集（`user_id, item_id, category_id, behavior_type, timestamp`），本方案中的分层 / 聚类 / 可视化框架可直接复用，并补充漏斗与留存模块。

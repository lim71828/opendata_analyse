# 社交电商用户购买行为预测 —— 全流程数据分析报告

##业务背景与痛点

**业务背景**：小红书、抖音等社交电商平台的用户转化遵循“曝光 → 种草(点赞/评论/关注) → 兴趣(领券) → 意愿(加购) → 转化(用券/购买)”的长链路。平台每天产生海量内容曝光，但其中真正下单的用户占比有限，运营团队需要在千人千面的信息流中，提前识别“最可能购买”的用户与商品组合，将有限资源投入到高转化人群。

**业务痛点**：

1.  **营销成本高**：无差别地向全量用户投放优惠券/推送，资源被大量低意向用户稀释，ROI 低；
2.  **缺乏可解释的识别手段**：高潜用户圈选长期依赖运营经验，缺少数据驱动的量化依据；
3.  **转化窗口短**：从曝光到购买的时间窗口有限，若不能在用户“热度最高”时触达，转化即流失（`last_click_gap` 越短转化越高）。

**项目目标**：基于用户、商品、社交互动与行为序列特征，构建购买转化预测模型，实现高潜用户圈选，为运营提供“触达谁、发什么券、何时触达”的可执行建议。

------------------------------------------------------------------------

## 0. 摘要

本报告基于一份包含 **100,000 条** 用户-商品交互记录、**32 个字段**（31 个特征 + 1 个二分类目标 `label`）的社交电商数据集，完成了从数据质量检查、探索性分析、特征工程到模型训练与运营建议的完整分析链路。

**核心结论**：

- **数据质量优秀**：无缺失值、无重复行，字段语义与取值范围全部通过一致性检查；
- **目标分布**：正样本（购买）占比 **45.0%**，正负比约 **1:1.22**，而非描述中声称的约 1:4（详见 §1.4 的说明）；
- **最强预测信号来自行为序列特征**：加购（add2cart）、用券（coupon_used）、领券（coupon_received）与购买高度相关，XGBoost 特征重要性中 `add2cart` 单特征贡献约 45.6%；
- **最佳模型**：XGBoost 测试集 **AUC = 0.7769**，经阈值优化后 F1 由 0.657 提升至 **0.692**；
- **运营圈选可行**：按模型概率 Top 20% 圈定的高潜用户，实际购买率达 **82.8%**，是全局（45.0%）的 **1.8 倍**。

### 1.4 ⚠️ 与数据描述的差异

原描述称“正负样本比例约为 1:4”。**实测该比例约为 1:1.22（正样本 44.98%），属于接近均衡的二分类**。这一差异会直接影响建模策略： - 接近均衡时无需做 SMOTE / 欠采样等重平衡处理，直接用原始分布训练即可； - 模型评估时以 **AUC / F1** 为基准（对类别比例不敏感），而非仅看 Accuracy； - 若描述属实（1:4）反而需要重平衡，本报告按实测分布给出结论。

## 3. 数据预处理与特征工程

### 3.1 预处理要点

1.  **缺失/重复**：核实为 0，无需清洗；
2.  **异常值**：互动长尾数据判定为业务特征而非错误，保留；
3.  **偏度处理**：对 14 个右偏特征（消费、价格、点赞/评论/分享/收藏、互动率、购买意向、社交影响力等）做 **log1p 变换**，变换后偏度由最高 73 降至 1 左右，改善线性模型表现与数值稳定性；
4.  **逻辑一致性**：折扣率∈[0,1]、情感得分∈[0,1]、全部二值字段∈{0,1}，全部通过。

### 3.2 特征工程

在**不触碰原始数据、不引入目标泄漏**的前提下，派生 15 个新特征：

| 类别 | 派生特征 | 含义 |
|----|----|----|
| 高基数编码 | `item_popularity` | 商品被曝光频次（热度） |
| 类目编码 | `cat_*` one-hot + `category_code` | 6 类目的哑变量 |
| 价格感知 | `discount_depth`、`effective_price`、`discount_amount`、`price_value` | 折扣深度、折前价、让利额 |
| 内容丰富度 | `content_richness` | 图片数 + 是否视频 |
| 用户活跃 | `activity_score` | 购买频次 + 浏览对数 |
| 社群黏性 | `social_connectivity` | 关注 + 粉丝 |
| 内容热度 | `total_engagements_log`、`video_engagement` | 互动总量、视频×互动 |
| 漏斗阶段 | `funnel_progress` | 领券+加购+用券叠加 |
| 时间衰减 | `recency_burden` | 点击间隔 × 非新鲜度 |
| 购买力 | `spend_intensity` | 累计消费 / 注册天数 |

最终建模特征 **63 个**。

### 5.1 运营建议（回扣痛点）

结合业务痛点，上述模型结果可直接转化为三类运营动作：**① 精准圈选高潜用户（降成本）**——按 Top 20% 概率分群优先触达，避免无差别投放；**② 行为链路的即时干预（抓窗口）**——针对已加购/领券未购用户在热度窗口内触发推送；**③ 差异化的内容与券策略（提转化）**——按用户等级与互动深度匹配“种草”内容或折扣钩子。具体策略如下：

| 对象 | 策略 |
|----|----|
| 加购未购用户 | 定向发放**限时优惠券 + 库存紧张提醒**，缩短决策周期（`last_click_gap` 越短转化越高） |
| 领券未用用户 | 推送**用券倒计时 + 相关商品推荐**，提升用券率 |
| 高互动低购买用户 | 强化“种草”内容（视频、多图）向购买引导，`video_engagement` 与热度特征有增益 |
| 低等级新用户 | 以低价、高折扣品（`discount_depth`）作为首购钩子，提升用户等级与消费粘性 |
| 高潜人群运营 | 按 Top 20% 概率分群做**优先触达**，预计转化率可达 80%+，降低营销成本 |

## 6. 用户价值分层与增收运营策略

> 本章回答“针对每一类用户，怎么运营才能使他们花更多的钱”。完整版见 `output/用户价值分层与增收策略.md`。

### 6.1 分层方法

先尝试 KMeans 无监督聚类，但数据中用户层面**没有天然的消费能力簇**（各簇客单价均 ≈¥110、频次均 ≈12，仅购买率不同）——因为每条记录是“用户-商品”快照，`price` 是当下浏览商品的价格而非用户历史消费水平。因此改用 **RFM 式业务价值分层**：按 `历史累计消费(total_spend)` × `购买意向(purchase_intent)` 切成 6 类，使各档在“花钱能力”上真实拉开差距。

### 6.2 分层画像

| 用户层        | 占比  | 购买率 | 客单价 | 累计消费 | 特征定位                    |

| 高消费·高意向 | 16.4% | 61%    | ¥110   | ¥5526    | 意向强、用券率高 → 核心金矿 |
| 高消费·低意向 | 17.0% | 30%    | ¥110   | ¥5521    | 有钱但当下不买、不领券      |

### 6.3 分层的增收策略

围绕“花更多钱”的**客单价 ↑ / 频次 ↑** 双杠杆，各层策略如下：

| 用户层 | 核心策略 |
|----|----|
| 高消费·高意向 | **提客单**：升级款/满减凑单；**稳复购**：会员体系绑定防流失、提 LTV |
| 中消费·高意向 | **提客单**：中高价连带款/升级套装；**稳复购**：会员权益绑定 |
| 低消费·高意向 | **守客单**：买贵包退/正品保障；**提频次**：会员日/复购券，意向转复购 |
| 高消费·低意向 | **先破冰**：首单立减/新人礼；**补种草**：多图+视频+买家秀，建立券心智 |
| 中消费·低意向 | **先破冰**：领券倒计时+满减凑单；**补内容**：提升种草→加购 |
| 低消费·低意向 | **逐步提频**：低价高性价比品促复购，积累信任后再升档推荐 |

### 6.4 增收杠杆优先级

1.  **提客单价（主杠杆）**：所有“高意向”层的客单价均未显著高于大盘（≈¥110），说明**意向强的用户未被充分转化为高价购买**——升级款/连带推荐空间最大；
2.  **提频次（次杠杆）**：购买频次约 12 次/月已是高位，频次空间有限，应以“会员绑定”维稳为主、小幅拉升为辅；
3.  **低意向层破冰（前提）**：约 51% 用户（低意向 3 档）几乎不领券不买，必须先靠首单优惠与内容种草激活，否则增收无基础。

## 7. 局限性与后续方向

1.  **类别比例与描述不符**：实际为近似均衡，后续若获得 1:4 版本数据需重新评估重平衡策略；
2.  **无时间序列维度**：数据集只有横截面快照，无法做时序切分与时序特征（如滑动窗口行为趋势）；
3.  **`add2cart` 强依赖**：行为链特征主导预测，需在真实业务中验证时间窗设定以避免泄漏；
4.  **可尝试的进阶方向**：目标编码（防泄漏版）、LightGBM/CatBoost、Stacking 集成、SHAP 可解释性分析、按类目分模型、基于多期用户行为的分层运营。
